# 路线图

[English](../roadmap.md) · [文档导航](README.md)

里程碑定义成果，不承诺发布日期。缺少游戏环境时继续不依赖它的工程工作；离线通过不提升未实测原生接口的状态。

| 阶段 | 成果 | 验收边界 |
| --- | --- | --- |
| H0 仓库与程序身份 | 公开协作／格式／CI 基线、只读 PE 核查工具 | 源码、损坏输入、语言／Schema、安装后 CLI；当前实现范围 |
| H1 原生观察 | 程序身份、模式、安全阶段、相机与世界查询 | 非改写观察、状态转换及安全退出，仍需真实宿主 |
| H2 真实 Fabric 客体 | 实际 MC 生产／消费、重复放置移除及真实图层或几何 | Fabric 运行、协议一致、有界队列、代次与重连；可独立部分不等待 H1 |
| H3 同一场景 | 正确遮挡和原生方块碰撞 | 双运行时、玩家／敌人／投射物阻挡与移除；导航分开 |
| H4 伤害与 TNT | 双向普通伤害及爆炸 | 权威生命值前后、归因、重复、死亡、重连，不用强制死亡替代 |
| H5 可玩系统 | 控制权交还、背包、物品、建造、生物 | 双方真实运行时的端到端玩法与性能测量 |
| H6 持久化与交付 | 保存桥接状态、安装、升级、卸载及退出恢复 | 一次性测试数据、兼容与恢复证据，并另行批准发行 |

隔离的原生几何候选表可以有界管理坐标变换后的 AABB，但尚无消光物理注册、碰撞过滤或经过真实游戏验证的资源销毁。

## H2 验收顺序

**H2-A 方块事件与双向 IPC：** 已有源码实现和受控 Java／C++ 进程测试。固定依赖解析、Fabric 编译及生产 JAR 检查已在 Ubuntu/JDK 21 的 [CI #38892925451](https://github.com/ranzevor/HarranCraft/actions/runs/38892925451) 通过；普通云端 Fabric CI 仍仅编译。[本地日志](validation-20261017.md)记录服务端 GameTest 3/3 通过及客户端首次桥接接入失败；所附报告将直接 Gradle 执行归于 `b1b6234eb81955cc170cc5e8ce66df5191073ca4`，日志未独立证明这些命令的源码身份。继续[本地验证](guest-validation.md)：全部七项客户端场景、三张截图、真实世界／模式转换及完整 Windows Fabric 生产 JAR 检查。Linux 和 Windows/MinGW 原生进程检查按版本分别记录于 [PR #2](https://github.com/ranzevor/HarranCraft/pull/2)。客体接收嵌入式私有管道，本批不包含最终用户启动器或消光端点。

**H2-B 真实客体图形输出：** 已有静态 BakedModel 采样、独立 Java／C++ 渲染记录、可选客户端异步发布及原生候选接收与失效控制；已新增源精灵 ARGB 异步批次发布、原生完整性候选缓存及资源重载撤销。本地客户端失败时尚未执行模型／像素采样，也未验证重载回调；仍需完整动态材质／最终显存图集、实际消光绘制、双相机深度标定和游戏验证。先完成 H2-A 实机验收，再传输渲染网格并证明真实帧、相机投影及消光深度对应，才能推进 H3。流体、方块实体、最终光照及宿主遮挡仍需单独完成。

H1 观察实验保持独立可测。宿主修改仍受真实程序版本、模式与引擎阶段证据约束；源码及协议工作不等待无关游戏环境。

[受控投影契约](camera-projection.md)提供相似变换标定、明确的相机／视口约定，并将有界当前采集绑定到有效材质、几何及宿主观察身份。该能力用于推进 H2-B 标定；调用方提供的关联与投影参数仍须取得实际游戏采样及同步证据，才能满足 H3 验收。

[D3D11 深度契约](d3d11-depth.md)新增绑定当前构建／相机身份的有界引用管理与只读深度视图准备。Windows WARP 回归在两个游戏之外检查受控深度遮挡；真实场景阶段识别、原生绘制提交、材质上传及碰撞注册仍是 H3 验收要求。

完整目标仍为双运行时融合，换模型／贴图、窗口覆盖及仅客体生效的交互不能满足 H3–H6。
