# 架构与所有权

[English](../architecture.md) · [文档导航](README.md)

离线核查工具 `hc-inspect` 的数据流为：明确文件参数 → 有界 PE 解析和流式哈希 → 带版本号报告。输入只读，报告按参数位置编号；解析器不进入游戏进程，也不批准原生调用。

H2-A 源码新增 Fabric 方块适配器、区块变化观察、Java 会话／传输核心及独立 C++ 测试进程。受控进程测试覆盖协议及生命周期；Ubuntu Fabric、GameTest 源码编译和生产 JAR 检查已通过，真实 GameTest 尚未执行。嵌入接口接收调用方自有私有管道，尚无最终用户启动器。[方块桥接契约](bridge.md)

Windows [主模块身份探测](host-observation.md#windows-主模块身份探测) 可通过固定 C ABI 只读获取进程主模块对应的磁盘文件指纹，但不证明内存映像、游戏模式或回调安全。独立的 [H1 观察核心](host-observation.md) 已实现明确程序指纹检查、单人／只读阶段证据门禁、会话代次，以及世界／相机／帧／捕获的精确对应。宿主与客体的裁剪空间转换仅为数学实现；尚未定位消光实际回调或读取原生相机与深度资源，也未默认认可任何游戏构建。[组合构建门禁](host-observation.md#宿主构建组合身份) 同时匹配 EXE 与指定 DLL 指纹，发现模块缺失或变更便撤销会话和相机身份。

独立的[几何记录编解码器](geometry.md)可将真实 Fabric 碰撞体积快照编码成有界记录并交由原生测试对端解析；客体提供与方块会话绑定的可选异步几何输出，服务端线程不阻塞等待写入；原生有界流接收器能验证分片记录并在协议错误或 EOF 时撤销候选，但目前只在受控进程测试中执行；尚未接入消光进程、原生碰撞体注册或渲染链路。

仅客户端使用的[烘焙模型观察器](render-model.md)读取真正的静态 Minecraft BakedModel 顶点和相机姿态，附加逻辑会话、世界、相机、帧、采集身份，与物理碰撞 VoxelShape 独立。[渲染记录 v1](render-wire.md)通过 Java／C++ 编解码及受控进程测试保留四边形和身份。客户端[源精灵采样与材质发布](texture-wire.md)读取有界 NativeImage ARGB，取得完整模型／精灵清单后分别排入独立异步输出；任一输出失败立即使另一条输出失效并注销发布器，不等待客户端所属线程再次调用。

原生 [MaterialCoordinator](../../include/harrancraft/material_coordinator.hpp) 在单一所属线程上关联两条 FIFO 流，允许跨流任意先后及分片交错，只提供会话代次／世界／相机／帧／采集身份完全匹配的完整材质。新模型撤销同位置旧材质；已被替换的在途采集仅保留有界校验记录，不会恢复旧像素。[组装边界与生命周期](texture-wire.md#跨通道材质协调)限制待关联采集、位置、记录身份、保留数据和绝对期限，即使输入静默也需要定期轮询。任一流结束或失败都清空整个关联会话。协调器持有 CPU 数据，I/O 端点由调用方负责；最终 GPU 图集、消光图形资源注册、真实深度标定和游戏帧同步仍未实现。

[相机标定与采集投影契约](camera-projection.md)新增版本化相似变换、刚体相机、明确裁剪／viewport 约定及绝对坐标误差检查。所属线程投影器核实独立客体／宿主采集键、完整材质及显式关联的最新几何回执，只保留最多 3,072 点的单个 CPU 结果。每次轮询或快照都复核来源；更新的几何回执即使属于另一位置，也会使旧关联失效。客体相机参数仍为受控输入，现有 v1 协议不证明真实运行时帧对应或场景遮挡。

Windows 专用的 [D3D11 深度附件](d3d11-depth.md)将调用方当前即时上下文的颜色／深度绑定及视口，与完整组合构建会话和 P2 相机契约核对。它拥有一个只读深度／模板视图、设备及所选颜色视图引用，并限制所引用源纹理的像素存储量；访问时复核身份与当前绑定，失败或显式撤销时释放这些引用。模块不绑定绘制管线，也不绘图。已注册的 WARP 测试执行受控软件图形操作；实际消光场景阶段、深度内容及安全提交阶段仍须通过宿主接入证明。

计划中的消光适配器负责宿主对象身份、原生世界查询、相机／深度采集及经过验证的引擎调用；真实 Fabric 客体负责 Minecraft 背包、方块、物品及自身模拟。桥接传递版本化快照和命令，不额外建立一套独立决定双方生命值或对象状态的权威。

| 状态／操作 | 归属与验收 |
| --- | --- |
| MC 放置／移除 | 客体世界变更；宿主确认对应自有碰撞体，失败时拒绝或回滚 |
| 宿主实体与生命值 | 以宿主生命周期和生命值为准，客体代理不独立强制原生死亡 |
| MC 实体与生命值 | 客体模拟为准，宿主事件带来源身份且只结算一次 |
| 输入焦点 | 每个路由动作只有一个接收者，失焦／断连释放所有按住状态 |
| 碰撞资源 | 适配器持有自建几何与注册，分配／激活均对应回滚与释放 |
| 画面与相机 | 带原始相机、会话代次及捕获身份；拒绝错误配对 |

未来宿主采用 Windows x64 工具链，客体已固定[候选工具链](compatibility.md)，已在 Ubuntu CI 完成依赖解析及编译，仍需真实游戏验证。Garry's Mod 不是组件。原生几何与深度感知 GPU 合成须通过宿主实验选择，不能提前宣称某一路线已成立。

`include/harrancraft/wire.hpp` 定义已实现的版本 1、512 字节小端协议；Java `Frame` 提供匹配编码与严格校验，并通过受控端点的参考帧和真实进程测试。共享内存名称必须独立，不能复用参考工程的名称或假定其布局相同。

每个游戏事件携带来源、会话代次、唯一身份和目标生命周期；限制队列与每次更新工作量，定义饱和和确认行为。重连不得重放旧伤害或复活已删除碰撞资源。不兼容修改须升级协议并验证生产者／消费者的拒绝或迁移。

宿主修改依赖已接受程序指纹、单人模式正向识别及安全引擎阶段；未知或禁止状态使修改通路失效。Present／窗口消息只可作为观察候选，不能直接认定安全修改点。修改回调中不进行阻塞等待、文件 I/O 或同步 GPU 回读。

H2-A 仅执行 Minecraft 方块操作。服务端线程在访问前检查模式，禁止状态使会话失效；流工作线程不访问世界。区块回调观察实际变化，事件或回执发送失败时关闭会话而不重放修改。断连后须在新代次重新取得快照，因为确认失败不会自动回滚已提交的 Minecraft 变化。表中的宿主碰撞确认和跨运行时回滚仍是后续融合契约。

渲染须验证场景深度、相机与帧对应，或等价的原生几何遮挡，并覆盖透明层、HUD、抖动与窗口变化。原生方块碰撞须分别阻挡玩家、敌人与投射物，删除后不再阻挡；AI 导航独立验收。双向伤害和爆炸先验证普通非致死伤害及归因，不用 Kill 替代。

退出或会话失效时，先停止修改并失效化队列／代次，再释放输入，通过安全生命周期清理自有对象、恢复隐藏状态，最后解除图形和通信资源。无法证明安全销毁时保留未完成清理状态，不能丢弃所有权登记后声称恢复。
