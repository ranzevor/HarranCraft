# 消光宿主观察核心

[English](../host-observation.md) · [架构](architecture.md) · [宿主接口研究](../host-research.md)

C++20 只读观察核心位于 [host_observation.hpp](../../include/harrancraft/host_observation.hpp)，对应[隔离 CTest](../../native/tests/host_observation_test.cpp) 不加载或启动游戏。

## 构建与会话身份

`ImageIdentity` 包含 32 字节 SHA-256、文件长度和 AMD64 PE 机器类型（`0x8664`）。`Observer` 使用由调用方明确提供的允许列表；空列表拒绝所有构建。CTest 的合成身份仅用于测试，不代表已经认可任何《消逝的光芒 1》版本。

未来的 Windows 适配器必须独立核验原生可执行文件，正向识别单人模式、当前世界身份和安全的引擎**只读**阶段。回调自行声称的状态或版本字符串匹配不能证明上述条件。本模块没有预先认可的消光游戏构建。

只有构建身份匹配，且状态为 `single_player / playing / verified_engine_read`、世界身份非零时，才建立观察会话。合作、入侵、加载、关闭、窗口／Present 和未知状态全部拒绝。采集或查询时如果上下文变化，则撤销会话。通过只读阶段检查也不授予任何宿主修改能力。所有观察操作必须在创建该对象的线程执行；跨线程访问直接失败，不传递原生引擎对象指针。

## Windows 主模块身份探测

Windows x64 [宿主探测 DLL](../../native/host/host_probe_windows.cpp) 通过 [host_probe.h](../../include/harrancraft/host_probe.h) 提供版本化 C ABI。`hc_probe_current_executable_v1` 测量当前进程的主可执行文件；`hc_probe_loaded_module_v1` 按受限 ASCII DLL 文件名查询**已经加载**的模块，读取期间增加并在结束后释放模块引用。两者都不枚举其他进程、不启动游戏、不加载额外 DLL、不搜索安装路径。调用方提供精确缓冲区大小；成功返回 56 字节的 ABI 版本、AMD64 PE 类型、文件长度和 SHA-256。非法缓冲区不写入，其他失败清空输出。

探测使用主模块文件名，以拒绝共享写入的只读方式打开文件，验证对应的 AMD64 PE32+ EXE／DLL 类型，并通过 Windows CNG 流式计算最多 512 MiB；返回前复核文件大小、文件索引和修改时间。失败区分文件不可用、不支持格式、超限、读取过程中变化和系统错误。C 接口不输出文件路径或进程句柄。

这些值只是**与当前已加载模块路径关联的磁盘文件指纹**。同名 DLL 可能导致按文件名查找存在歧义，因此单靠名称查询不能批准整个宿主构建：不能证明已加载内存与所打开路径为同一文件对象，也不是游戏附加许可、多人模式判断或安全回调证据。哈希仅在受控初始化阶段执行，不能放到游戏更新／图形回调或加载器锁下。H1 观察门禁仍需独立验证构建允许列表以及可信模式／阶段证据；不会自动开放任何消光版本。

## 帧对应关系

相机样本包含会话代次、世界、相机、帧、捕获身份，以及位置、列主序视图／投影矩阵。重新附加会增加代次；建立替代会话失败时同样使旧会话失效。当前代次内帧号与捕获号必须严格递增；缺失、乱序、非有限数值及世界不符的样本均拒绝。只保留最新样本；查询必须同时匹配五项身份及未改变的会话证据。世界切换、模式丢失、停止均清除样本。

`project_clip` 使用明确的 Minecraft→宿主仿射矩阵，再应用捕获的视图和投影矩阵，输出齐次裁剪空间坐标；它不是屏幕像素或遮挡证明。矩阵使用列主序、列向量。真正接入前需实测坐标轴、单位、手性、投影约定与帧对应关系；合成投影和图像对齐不等于获取宿主深度缓冲。

## 隔离验证

`python tools/test_bridge.py` 通过现有 CMake/CTest 运行 `host-observation`，同时保留原有原生线协议及 Java 进程回归。新增测试覆盖构建、模式及阶段拒绝、代次、相机替换、帧对应、浮点异常、线程归属、世界切换与停止恢复。Windows x64 还会在受控测试进程中实际加载 DLL，核对 C ABI、重复调用和句柄回收，并使用 Python 独立计算测试 EXE 及已加载探测 DLL 的 SHA-256 进行比较。测试不证明真实游戏回调安全、游戏二进制身份、相机精度或原生物理。

实际消光引擎挂接、安全回调来源、实时相机／世界读取、自有原生资源销毁及原世界交互仍须分别完成 H1/H3 验收。
