# 方块桥接协议

[English](../bridge.md) · [架构](architecture.md) · [本地验证](guest-validation.md)

## 端点与状态归属

`GuestConnections.attach(server, input, output)` 在 Minecraft 服务端线程接入调用方自有私有管道。调用方必须同时提供两个流、控制对端，并确保关闭流能够解除阻塞 I/O；接入后流归桥接管理。进程管道应构造 `PipeLink(input, output, cancelIo)`，通过 `GuestConnections.attach(server, link)` 接入并保留传输句柄。取消回调在独立工作线程上仅执行一次，只能解除本连接明确持有的对端资源；桥接不自行发现或终止进程。接入被拒绝时，传入的 link 仍由调用方管理。接口不创建监听端口、进程启动器或消光适配器。`native/tests/bridge_peer.cpp` 是协议测试进程。

`MinecraftBlocks` 在嵌入式单人服务器中读取和条件修改已加载位置。加载、停止、独立服务器或远程／局域网开放状态拒绝接入并使现有会话失效。这些 Minecraft 检查不能识别消光模式。读取、修改、接入、断开和变化观察归服务端线程；流 I/O、对端取消与关闭操作由守护工作线程执行。

位置由维度标识和有符号 X/Y/Z 坐标组成。高度或世界边界之外的位置无效，维度不存在或区块未加载时不可用；接口不强制加载区块。方块状态采用完整规范标识及按名称排序的属性，例如 `minecraft:oak_log[axis=x]`。未知标识、重复或无效属性及省略默认属性的非规范形式均被拒绝。本批拒绝替换已有或目标方块实体，以保留其数据；后续方块实体能力并未取消。

## 版本 1 数据帧

[wire.hpp](../../include/harrancraft/wire.hpp) 是原生布局权威，Java [Frame](../../guest/src/main/java/io/ranzevor/harrancraft/bridge/Frame.java) 提供匹配实现。每帧固定 512 字节、小端编码，不直接传输原生结构体内存。

| 偏移 | 字节数 | 字段 |
| --- | --- | --- |
| 0 | 4 | 魔数 `0x31435248` |
| 4 | 2 | 版本 `1` |
| 6 | 2 | 消息类型 |
| 8 | 8 | 会话代次 |
| 16 | 8 | 请求或事件身份 |
| 24 | 4 | 来源：原生端 `1`、客体端 `2` |
| 28 | 4 | 状态 |
| 32、36、40 | 各 4 | 有符号 X、Y、Z |
| 44、46、48 | 各 2 | 维度、预期状态、当前／目标状态长度 |
| 50 | 2 | 必须为零的保留字节 |
| 52 | 8 | 引发变化的命令身份，无则为零 |
| 60 | 4 | 必须为零的保留字节 |
| 64 | 64 | 维度文本 |
| 128 | 192 | 预期／原状态文本 |
| 320 | 192 | 目标／当前状态文本 |

文本仅含 ASCII 32–126 的可打印字节，未使用容量必须补零。代次、身份及原因身份范围为 `0..2^63-1`，有效代次必须为正。无效帧头、填充、长度、字符、截断帧、类型、来源及状态会拒绝帧并终止传输。布局改变须升级协议版本并验证对端拒绝或迁移。

消息类型：HELLO `1`、WELCOME `2`、GET `3`、SET `4`、RESULT `5`、EVENT `6`、PING `7`、PONG `8`、CLOSE `9`。状态：OK `0`、STALE_EPOCH `1`、INVALID `2`、UNAVAILABLE `3`、CONFLICT `4`、FORBIDDEN `5`、RETIRED_ID `6`、CAPACITY `7`、UNSUPPORTED_STATE `8`。

## 顺序、订阅与恢复

原生对端首先发送空 HELLO，代次及身份为零、原生来源、OK 状态。WELCOME 返回客体分配的新正代次。后续 GET、SET、PING、CLOSE 使用该代次、正请求身份、原生来源、OK 状态及零原因身份。PING 消息体为空，由相同身份的 PONG 回应；CLOSE 终止会话，不返回回执。

GET 只携带位置，读取成功后订阅该位置。SET 另含精确预期状态和目标状态；替换前与权威世界比较，不一致时返回 CONFLICT 及观察状态。SET 成功读取的位置即进入订阅，即使后续替换被拒绝。RESULT 携带请求身份、状态及观察到的方块状态。无变化的 SET 不产生变化事件。

`WorldChunkMixin` 在区块修改返回后观察原状态和实际当前状态。已订阅位置变化产生 EVENT，使用独立递增事件身份并保留前后状态及因果。SET 执行期间产生的变化采用原生来源及该命令身份；独立 Minecraft 变化采用客体来源和零原因身份。EVENT 可以先于对应 RESULT 到达；此观察不代表消光碰撞或渲染已经生效。

单会话最多订阅 128 个位置、保存 512 份请求／响应回执。重复相同的已保留请求只重发回执，不重复执行；同身份不同内容返回 CONFLICT。回执淘汰后，低于或等于高水位的身份返回 RETIRED_ID。重连不复用旧回执或订阅。收发队列分别最多 256 帧，每次 tick 最多处理 32 个请求；执行命令前须至少有 129 帧输出容量。队列饱和、发送失败、非法输入、禁止模式、断连或有效会话活动间隔超过 30 秒会使连接失效。已接受的 PING 可以维持空闲连接。

失效先停止修改并清除回执、订阅和排队任务，再启动对端取消并分别关闭两个流。队列交接与失效按顺序执行，迟到的读取不能重新填入已关闭的输入队列。已经开始的写入仍可能送达字节，因此接收端必须保留代次校验。适配器异常会关闭会话并保留失败，不转换为成功响应。EVENT 或 RESULT 发送失败前，Minecraft 可能已完成修改；断连不会自动回滚权威世界。重连时取得新代次，通过 GET 重新读取并协调状态，再发出新的条件修改；不得盲目重试旧命令或推断宿主已经提交。

## 结束确认与自有资源

`isOpen() == false` 只表示连接拒绝通信，不表示 I/O 已结束。只有读取、写入、取消及两个关闭工作线程全部结束，`PipeLink.isTerminated()` 才返回 true；报告清理成功前还必须检查 `cleanupFailure()`。关闭仍在进行或发生异常时，保留 link 句柄，先处理持有的对端资源，再建立替代连接。这些查询不会等待；Minecraft tick 或区块回调中不得 join 工作线程或等待进程。

`stopReason()` 保留首个结束原因：主动关闭、输入 EOF、输入／输出失败、输入／输出饱和或中断。`ioFailure()` 保留 I/O 异常；`cleanupFailure()` 保留取消／关闭异常，并以 suppressed 异常保存同时发生的错误。它们是嵌入接口诊断，不是玩法事件或协议字段；帧版本及布局不变。

双流构造方法继续用于仅靠 close 即可解除阻塞的流。Java [InputStream 契约](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/io/InputStream.html#readNBytes(int)) 没有给出通用的异步关闭或中断保证。原生测试进程使用显式的自有进程取消回调和有界退出检查，测试路径不会选择游戏进程。
