# 程序文件核查契约

[English](../inspector.md) · [文档导航](README.md)

## 输入与行为

`hc-inspect [--language LANGUAGE] [--json] [--exports] FILE ...` 读取 1–16 个明确指定的普通文件。接受 AMD64（`0x8664`）PE32+（`0x20b`）EXE／DLL，节区数量为 1–96 且不得重叠。工具不将映像加载执行、不安装程序、不搜索游戏，也不将输入发往服务。

文件按只读方式打开；RVA 必须映射至真实文件字节，虚拟零填充不能作为元数据。核对文件头／表边界、导出序号、字符串、资源遍历与整数范围，再以流式方式计算整个已打开文件的 SHA-256。前后文件元数据和读取长度必须一致；检测到并发变化时核查失败。复现应使用未变化的输入，此机制不是对抗恶意并发写入的快照协议，也不是完整的 Windows 加载器校验器。

解析资源上限：每文件 512 MiB，累计元数据读取 8 MiB，导出地址槽及名称指针各 65,536 项，零终止导出字符串 4,096 字节，版本资源目录总计 4,096 个条目、三层深度。先校验数量再遍历／分配；哈希使用 1 MiB 分块。

## 输出

CLI 统一使用 UTF-8 输出。文本模式显示输入位置、类型、大小、SHA-256、导出数量及固定文件版本。`--json` 使用[报告 Schema v1](../../schemas/inspection-v1.schema.json)；`--exports` 增加非零导出槽、序号、所有别名及转发字符串。仅序号导出的 `names` 数组为空。

报告不包含输入路径、文件名、导入库代码或原始资源数据。`input_index` 从 1 开始并保持命令顺序；导出名称不代表调用约定或游戏接口已经验证。

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 报告布局版本，当前为 1 |
| `tool_version` | 核查工具版本 |
| `results[].status` | `inspected` 或 `error`，不是游戏兼容状态 |
| `sha256`、`file_size` | 已打开文件的内容身份与字节数 |
| `machine`、`format`、`kind` | AMD64、PE32+、EXE／DLL 分类 |
| `coff_timestamp` | 原始 COFF 字段，不作为可靠产品版本或发行日期 |
| `file_versions` | 不重复的固定文件版本，缺失时为空数组 |
| `sections` | 节区文件偏移、RVA、大小及属性 |
| `export_count`、`named_export_count` | 非零导出槽及关联名称数量 |
| `exports` | 可选的详细导出表，包含别名与转发 |

文件名、内嵌版本及导出列表均不能作为兼容证书。宿主适配器还必须独立验证受支持程序指纹、模式和调用语义；当前报告没有 `compatible` 或受支持游戏承诺。

## 失败与退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部输入核查成功，或显示帮助／工具版本 |
| 1 | 至少一项输入失败，仍按原顺序保留成功结果 |
| 2 | 参数无效，通过 stderr 返回用法提示 |
| 130 | 完成前被中断 |

普通输入失败时，JSON 模式仍通过 stdout 输出完整报告，包含稳定错误码和本地化消息。参数错误和中断不输出部分 JSON；消费者必须检查退出码及每项结果。

错误区分无效文件头／布局、不支持的架构／格式、节区重叠、无文件支撑的 RVA、无效导出／资源、资源超限、输入变化、非普通文件及无法读取。不把原始堆栈或个人路径作为正常反馈。

## 语言与演进

语言优先级为 `--language`、`LC_ALL`、`LC_MESSAGES`、`LANG`；`zh`、`zh-CN`、`zh-SG`、`zh-Hans` 使用简体中文，其他值回退到 en-US，并规范化下划线和编码后缀。翻译键缺失时回退英文；提交检查要求两种语言的键和占位符一致。

机器字段及错误码不随语言变化。不兼容的报告修改须升级 Schema 版本并验证消费者；它与将来的游戏桥接 ABI 分开管理。格式来源见[英文契约](../inspector.md)。
